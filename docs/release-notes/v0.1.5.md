# mai2srt v0.1.5

本次更新修复了长音频在末尾被切成静音片段后整个任务失败的问题（[#5](https://github.com/fuxiaomoke/mai2srt/issues/5)），以及断句分行、精修页播放定位与转录过程中切换页面丢失界面的问题；此外新增了分层转录日志与版本更新提示。

## 问题修复

### 长音频在末尾失败

- 现象：长音频在转录到最后时整个任务失败：分块的位置刚好落在没有声音的尾巴上，末尾被切出一小段只有几秒的残余片段，服务端判定没有人声并予以拒绝，已经转好的部分一并作废。
- 修复：切块位置改为落在真实的停顿上，不再切出这种几秒钟的残余片段；即使某一段确实没有声音，也只跳过那一段继续转录，并在完成提示与日志中说明跳过的是哪一段。

完全没有人声的文件（例如误传的空录音）现在会在上传前直接说明原因，不再反复重试；此前被拒绝的上传还会在 playground 留下一条没有删除的会话记录，这一点也一并修正。

### 断句分行

- 现象：没人说话的静音会被并进字幕，单条字幕可以横跨十几秒；片头片尾的零碎语气词会单独成行；部分字幕的起始时间比实际开口晚，最多接近 5 秒，播放时看起来像字幕跟不上声音。
- 修复：超过 3 秒的停顿一律分行，静音不再被并进字幕；只剩一两个字的残行并回相邻行，确实是插话的一两个字仍然保留；行首时间只会提前，不再推后。

### 多人说话的对白合并

- 现象：相邻的两人对话容易被合并成一条多行字幕，正常的一人一句也会被凑到一起。
- 修复：只有真正的插话式重叠（说话人 X 说完、Y 接上、X 又回来）才合并成多行对白，普通的一人一句保持独立成行。

### 大模型断句

- 现象：断句请求里没有停顿的长短，模型偶尔在句子中间断开，或者为了凑长度硬断；问与答也常被并到同一行。
- 修复：请求中带上每处停顿的时长；3 秒以上的停顿必须断开，1.5～3 秒之间由模型按语义判断，问答即使中间没有停顿也分开成行。未配置大模型时行为不变。

### 精修页的播放定位

- 现象：MP3（尤其是可变码率）拖动进度条后，听到的位置与显示的位置不一致，长音频最多相差十来秒。
- 修复：音轨重新封装为带索引的容器，实测误差在 0.2 秒以内。转录完成后会提前做好这一步，通常打开精修页时已经就绪；尚未准备的文件首次打开约有 1 秒等待。转换后的音轨存进音频缓存，占用与原文件相当，可在设置页清理。长时间播放时界面的轻微卡顿也一并处理。

### 转录中切换页面

- 现象：转录过程中切换到设置页或精修页再回来，转录界面变成空白，此前的进度与日志都不见了。
- 修复：转录任务在后台持续运行，切换页面只影响显示。回来时进度、日志与结果仍然保留；任务在其他页面完成时会弹出完成提示；界面意外刷新后会自动接回正在运行的任务。

转录中不在转录页时，窗口右上角显示「转录中」标记，点击回到转录页。转录完成后，下次回到转录页会将它收为一条「上次：…」记录，可展开查看完整日志与结果；选择新文件即开始新的任务。

### 覆盖安装

- 现象：覆盖安装新版本后，后端可能无法启动，界面提示后端离线；卸载后重装同一版本又恢复正常。
- 修复：安装包在安装前会先清空旧版本的程序目录，避免残留文件冲突。用户数据（`~/.mai2srt` 与 `文档\mai2srt`）不受影响。

## 新增功能

### 转录日志

转录日志分为两层：默认只显示能直接看懂的进度与结果，技术细节收在「详细日志」里。以前失败时日志末尾会跟一整段英文报错，现在只给一句说明；「复制诊断」把版本信息与完整日志一并复制，反馈问题时可以直接粘贴。日志的语言跟随界面语言。

### 版本更新提示

窗口左下角的版本号可以点开「关于」窗口，其中显示当前版本、是否有新版本以及该版本的更新说明，并提供下载入口。启动时检查一次，此后每天最多一次；可在该窗口中关闭自动检查。该功能只做提示，不会自动下载或安装。

## 安装

下载下面的 `mai2srt_0.1.5_x64-setup.exe` 安装，FFmpeg 已随包内置。可以直接覆盖安装。

首次安装可能出现 Windows SmartScreen 蓝窗（安装包未签名）→ 点「更多信息」→「仍要运行」。附件中的 `SHA256SUMS.txt` 可用于校验下载是否完整。

## English

This release fixes long audio failing at the end, where the tail was cut into a few-second stub with no speech in it and the server rejected the whole job ([#5](https://github.com/fuxiaomoke/mai2srt/issues/5)). It also fixes line breaking, the seek position in the refine player, and the transcribe screen losing its contents on a page switch, and adds a two-layer transcription log and an update notice.

## Fixes

### Long audio failing at the end

- Symptom: long audio fails at the very end — the split lands on the silent tail and cuts off a residual piece only a few seconds long, which the server rejects for having no speech, so the whole job fails with what had already been transcribed discarded.
- Fix: cuts land on real pauses now and no longer produce such a stub; if a piece really does have no speech, only that piece is skipped and the run continues, with the skipped piece named in the completion notice and the log.

A file with no speech at all (an empty recording, say) now says so before uploading instead of retrying against the server. A rejected upload also used to leave an undeleted conversation on playground; that is fixed as well.

### Line breaking

- Symptom: stretches with no speech were merged into the subtitles, so a single line could span a dozen seconds; stray interjections at the head or tail of the audio became lines of their own; some lines started later than the speech they show, by nearly 5 seconds at worst, which reads as subtitles that cannot keep up with the audio.
- Fix: any pause over 3 seconds now starts a new line and silence is no longer folded in; lines of one or two characters left over fold back into their neighbours, while genuine one- or two-character interjections remain; starts only move earlier now, never later.

### Merging adjacent speakers into one line

- Symptom: adjacent back-and-forth between two speakers was easily merged into one multi-line subtitle, including ordinary cases where one person simply speaks one line at a time.
- Fix: only genuine overlap — speaker X talks, Y cuts in, X comes back — is merged into a multi-line dialogue; one person per line stays that way.

### LLM segmentation

- Symptom: the request carried no information about how long each pause was, so the model occasionally broke mid-sentence, or cut a line short just to reach a length; a question and its reply were often merged into one line.
- Fix: the request now states the duration of each pause; anything over 3 seconds must break, 1.5–3 seconds is the model's call based on meaning, and a question and its reply stay on separate lines even with no pause between them. Behaviour without an LLM is unchanged.

### Seek position in the refine player

- Symptom: seeking an MP3 (variable bitrate especially) played from a different position than the one shown — up to a dozen seconds off on long audio.
- Fix: the audio is remuxed into a container with an index, and the measured error is now under 0.2 seconds. A finished transcription prepares this in advance, so the refine page usually opens with it already done; a file that has not been prepared yet costs about a second on first open. The converted track lives in the audio cache, roughly the size of the source, and can be cleared in Settings. The slight stutter during long playback is gone as well.

### Switching pages while a transcription runs

- Symptom: switching to Settings or Refine mid-transcription and coming back left the transcribe screen blank, with the progress and the log gone.
- Fix: the job keeps running in the background and a page switch only affects what is displayed. Progress, log and result are still there on return; a run that finishes on another page reports itself with a completion notice; a reloaded UI re-attaches to the running job on its own.

While a run is live and you are on another page, a "transcribing" mark appears in the top-right corner of the window; click it to go back. When the run finishes, the next visit to the transcribe page folds it into one "last run" row whose full log and result can be expanded; choosing a new file starts a new job.

### Installing over an existing version

- Symptom: after installing a new version over an old one, the backend could fail to start and the UI reported it as offline; uninstalling and reinstalling the same version fixed it.
- Fix: the installer now clears the previous version's program directory before installing, so leftover files cannot collide. User data (`~/.mai2srt` and `Documents\mai2srt`) is untouched.

## New features

### Transcription log

The log has two layers: plain progress and results by default, technical detail behind a "detail log" button. A failure used to end the log with a block of English error output; it now gives one sentence, and "Copy diagnostics" puts the version information and the full log on the clipboard together, ready to paste when reporting a problem. The log follows the interface language.

### Update notice

The version number in the bottom-left corner opens an About window showing the current version, whether a newer release exists, what changed in it, and where to download it. It checks once at startup and at most once a day after that; automatic checks can be turned off in that window. This only informs you — nothing is downloaded or installed automatically.

## Install
